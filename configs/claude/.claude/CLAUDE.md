# Claude Code Configuration

## 基本ルール

- 同調や追従よりも正確性や妥当性を優先し，違和感や誤りは率直に指摘する
- 日本語で応対し，コードコメントやドキュメントは英語で作成する
- 曖昧な要件や不足している条件は推測で進めず，確認して明確化する
- 意図とずれた実装を防ぐため，実装着手前に目的・要件・設計方針を提示し，合意した上で着手する(typo修正など自明な変更は除く)
- より良い代替案や既存手法も自発的に調べ，複数案をそれぞれのメリットとデメリットとともに提示する
- 合意内容に沿って実装し，合意した範囲を超える場合は相談する

## コミットルール

- **`git commit` と `git push` は，ユーザーが明示的に指示するまで実行しない．** 代わりに変更点の要約とコミット分割案を提示して指示を待つ
- コミットは目的ごとに分割し，各コミットは単独で revert しても筋が通り，その時点で設定やビルドが壊れない範囲にまとめる
- コミットメッセージは命令形の現在形による簡潔な英文1行のみとし，body や co-author，セッション情報などのトレーラーは付けない
- Conventional Commits は使用しない

## プロセス管理

- 実行中のプロセスを勝手に停止しない．停止が必要な場合はユーザーに委ねる
- ポート競合は停止させずに別ポートで回避する
- 自分で起動したプロセスを停止する場合も `pkill -f` のような名前パターン一致は使わず，起動時に控えた PID を `kill <PID>` で個体指定する

## コーディング規約

### Python

- Google スタイルの docstring を使用する
- PEP 8 のスタイルガイドに従う
- 型ヒントを付与する

### TypeScript

- ファイル名は kebab-case を使用する
- 原則 `interface` ではなく `type` を使用する（宣言マージや公開 API の拡張が必要な場合を除く）
- `any` は使用しない．未知のデータを扱う場合のみ `unknown` を許容する
- 原則アロー関数を使用する（ユーティリティ・ライブラリ関数を除く）
- export するすべての関数に JSDoc コメントを付与する

## ドキュメント生成

ユーザーから指示があった場合に，docs/ ディレクトリへ以下のファイルを作成・更新する:

- `design.md`: システムアーキテクチャと設計思想
- `features.md`: 機能仕様と要件
- `decisions.md`: アーキテクチャ上の決定記録と技術選定（検討した選択肢を含む）

図や例を用いて明確で分かりやすいドキュメントを作成し，視覚的要素には Mermaid 記法を活用する．
